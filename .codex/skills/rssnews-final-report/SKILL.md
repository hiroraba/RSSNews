# RSSNews 最終報告

この skill は、RSSNews で修正や機能追加を終えた後の最終報告を整えるために使う。

## 目的

- 完了報告を短く保つ。
- このリポジトリで必須の報告項目を落とさない。
- 修正を知らない別メンバーでも、差分の概観をすぐ理解できる状態にする。

## 必須項目

最終報告には次を必ず含める。

1. 何を変えたか。
2. 何を検証したか。実行した build、test、Preview、未実行項目を明記する。
3. README を更新したか。更新していないなら不要と判断したことを明記する。
4. 別モデルの review を実施したか。重要な指摘の有無も明記する。
5. 別メンバー向けの概観説明。差分の意図と変更のまとまりが短く分かる説明にする。

## 書き方

- 先頭は変更結果を短く述べる。
- ファイル参照は必要なものだけ出す。
- 箇条書きは本当に列挙が必要なときだけ使う。
- changelog のようにファイルを並べすぎない。
- 追加提案や余談は、ユーザーが求めたときだけ入れる。

## 推奨テンプレート

```md
<変更結果の要約>

<build/test/Preview などの検証結果。未実行があれば理由も書く。> <README 更新有無。> <別モデル review の有無と重要指摘の有無。>

別メンバー向けの概観説明: <修正の意図、まとまり、影響範囲を 2〜4 文で説明する。>
```

## 補足

- bugfix と feature が同時にある場合は、ユーザーが理解しやすい単位でまとめる。
- review 未実施や test 未実行は省略せず、理由を書く。
- 既存の AGENTS.md の指示と矛盾する場合は、そちらを優先する。
